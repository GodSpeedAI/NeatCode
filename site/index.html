The problem was never that AI writes ugly code. It is that AI writes plausible code — locally correct, globally wrong. NeatCode installs the judgment of an engineer who has read the repository, before the agent writes and again before it claims to be done.

Neat in the joinery sense: a neat fit — exact, earned, nothing left over. Not tidiness. Not formatting.

One patch, all the way through

An agent was asked to resume a paused subscription without re-charging the current period. It produced code that compiles, passes its tests, and would have charged customers twice. Here is what NeatCode does with it.

The envelope supplies the meaning

A diff alone cannot be judged. The harness expands exactly one ring around each changed path — owning package, local imports, discoverable callers, related tests, governing instructions — and records what was actually run.

Four named failures, from three families

Each is a catalogue entry with a definition, observable signals, the reasoning failure underneath, its legitimate exceptions, and its likely false positives.

  • S1
    Retry of a non-idempotent effect introduced

    withRetry(3) wraps paymentIntents.capture() with no idempotency key. A timeout on a successful capture produces a second charge — invisible in tests, and it occurs under exactly the conditions retries exist for. state & concurrency

  • S2
    Fabricated guarantee introduced

    The docstring claims the operation is “atomic.” It performs a database write and then an external API call. Nothing makes those atomic; the word is doing work the code does not do. epistemic

  • S3
    Duplicated normalization worsened

    normalizePeriod re-implements roundToPeriodStart() in src/billing/period.ts:18, which two other call sites already use. Third divergent copy of one rule. authority

  • S3
    Canonical path bypassed introduced

    sub.status = 'active' assigns directly. SubscriptionState.transition() is the owner and is where audit records attach. context

The claim and the structure disagree

NeatCode compares what a repository says against what its imports and call graph express, and returns a verdict rather than an impression.

Claim
“Billing owns all subscription state transitions” — docs/adr/0004.md:12
Observed
SubscriptionState.transition() is the intended owner. src/api/admin/subscriptions.ts:88 and src/jobs/expiry.ts:31 already assign status directly; this change adds a third.
Verdict
Nominal — the authority exists and is bypassed by three of four write paths.
Consequence
Audit records attach to the transition function. Three paths produce subscriptions with no audit trail.

The sixth available verdict is coherent emergent alternative. Code that has diverged from its README into something internally consistent is not decayed — the documentation is wrong, and that is usually the cheaper fix. An audit that only ever recommends conforming to the document has confused documentation with architecture.

Five verbs

default build

Orient in the repository, state the contract, classify the change, choose the structure before the syntax, implement the smallest coherent change, then critique the diff before declaring completion. Prevention, not post-hoc inspection.

review

Judge a proposed change — working tree, staged, a commit, a range, a branch, a patch, a pasted diff. Every finding labelled introduced · worsened · exposed · pre-existing · resolved, so a patch is never billed for the file it landed in.

audit

Judge existing code — a file, a module, a subsystem, the repository. Morphology, architectural conformance, authority, boundaries, tests, operational readiness, debt. Read-only.

restructure

Keep the behaviour, replace the implementation strategy. Characterizes behaviour first — without a baseline, “preserves behaviour” is a wish.

study

Extract engineering DNA. Separates invariants from conventions from residue — patterns repeated only because they were copied. Optionally writes a portable engineering.md with provenance tags on every entry.

harden

Take happy-path code to production credibility: idempotency, concurrency, cancellation, recovery, observability, security boundaries, migrations, wiring. Structure preserved, completeness added.

Two questions do most of the work

Earnedness

What concrete constraint earns this complexity?

A second implementation that exists today is a constraint. A published interface is a constraint. A measured performance budget is a constraint. “It’s more extensible” is not. An interface with one implementation is not future-proofing; it is an unpaid tax on every future reader.

Evidence

What supports the claim that this is correct and complete?

“Tests pass” is a claim about a command you ran and an exit code you saw. The question that matters more than coverage: could this test have failed before the change? A test written from the implementation proves the implementation is self-consistent and nothing else.
